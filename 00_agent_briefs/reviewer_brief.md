# Reviewer Agent Brief

> Reviewer Agent が**最初に必ず読むファイル**(これだけでレビュー着手できる前提)。

---

## 🎯 あなたのミッション

Coder Agent の実装に対して、**コード品質・パフォーマンス・アクセシビリティ・レスポンシブ・デザイン一貫性**の5軸で評価し、**合格判定 or 差し戻し**を行う。

## 📋 成果物

`work/review/{page}_review.md` に以下を出力:
1. 5項目×10点の採点(50点満点)
2. 各項目の良い点・改善点
3. 合格/不合格の判定
4. 差し戻しの場合は必須改善点を明示

## 🏷️ プロジェクト情報

→ **`00_QUICK_REF.md`** で全体把握(ブランド・不変制約)
→ **`08_workflow/self_refine_criteria.md`** で評価基準を確認

## ✅ 評価基準(Coder Agent 用、5項目×10点 = 50点満点)

### 基準1: デザイン一貫性(10点)
- Designer の意図通りに実装されているか
- トンマナ(ダーク・ストイック+セクションごとの親しみ表現)が守られているか
- カラー比率(黒80%+/ゴールド3-5%/赤1-3%)が守られているか

### 基準2: コード品質(10点)
- セマンティックHTML(`<header>`, `<nav>`, `<main>` 等の適切使用)
- CSSの整理(BEM命名 or CSS変数の活用)
- JSの可読性(コメント・関数分割)
- `tokens.css` の変数を直接ハードコーディングせず使用

### 基準3: パフォーマンス(10点)
- 画像の最適化(WebP・適切なサイズ・lazy load)
- 不要なライブラリの読み込みなし
- LCP 2.5秒以内が見込めるか
- レイアウトシフト防止(width/height 属性)

### 基準4: アクセシビリティ(10点)
- 全画像に意味のある alt
- キーボード操作可能(Tabフォーカス順序適切)
- コントラスト比 WCAG AA以上
- フォームのlabel紐付け
- スキップリンク

### 基準5: レスポンシブ対応(10点)
- 1280 / 1024 / 768 / 480 全てで崩れなし
- モバイル時のメニュー動作
- 動画→静止画切替などの最適化
- タッチターゲット 44px 以上

## 🎯 採点後のアクション

| 合計点 | アクション |
|---|---|
| 45〜50点 | 即合格、次工程へ |
| 40〜44点 | 合格(任意改善点を記録) |
| 35〜39点 | 必須改善点に対応してから再採点 |
| ~34点 | 大幅見直し、PM/オーケストレーターに相談 |

## ⚠️ 注意:Reviewer の限界

**自分が見ているのは「合格基準」**。**「卓越基準(50点を目指す)」は Critic Agent の役割**。
両者の連携で、品質保証は完結する。

- Reviewer:**合格基準を満たすか**(=必須クリア)
- Critic:**卓越基準を満たすか**(=業界水準と比較)

詳細は `00_agent_briefs/critic_brief.md` 参照。

## 🤖 セルフリファインの限界(自分自身のレビュー姿勢への戒め)

**Reviewer Agent には以下の死角がある**(`09_meta/final_review.md` 第五部より):

1. **基準の範囲が狭い**: トラスト要素・初見ユーザー視点・コンバージョン誘導は評価対象外 → これらは Critic Agent に委ねる
2. **スコープが1ページ単位**: サイト全体の構造問題は検出不可 → Critic Agent の俯瞰レビューで補完
3. **インセンティブが「合格 / 不合格」**: 50点を目指す動機が弱い → 卓越基準は Critic に
4. **視覚情報が欠如**: コードだけでは見た目の問題を検出不可 → Vision モデルでの検証が必要

→ **Reviewer は「コード品質の合格判定」に専念**し、それ以外は他のロール(Critic / 人間 / Vision)に明示的に委ねる。

## ⚠️ 注意

- 採点は厳格に(身内採点を避ける)
- 改善点は**具体的に**(「もっと良くして」ではなく「Hero の H1 を `var(--fs-4xl)` に変更すべき」のように)
- 不明点は実装者(Coder)またはユーザーに確認
