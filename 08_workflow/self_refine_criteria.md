# セルフリファイン評価基準(2層構造版)

> ALPS LAB プロジェクトの評価基準。**「合格基準」と「卓越基準」を明確に分離**しています。
> Reviewer Agent は合格基準でゲート判定、Critic Agent は卓越基準で品質追求の役割分担。
>
> 設計の背景は `09_meta/final_review.md` 第五部参照(評価設計の構造的限界とその対策)。

---

# 🟢 Phase 1: 合格基準(必須クリア)

> **Reviewer Agent の責務**。40点で合格、35点未満は差し戻し。

## Designer Agent 用評価基準(50点満点)

### 基準1: ブランドコンセプトの表現(10点)
- 「北アルプスの麓から、本物の健康を研究する。」がファーストビューだけで伝わるか
- 長野発・自然・研究という独自性が感じられるか

### 基準2: トンマナの一貫性(10点)
- ダーク・ストイック基調が崩れていないか
- セクションごとの使い分け(ストイック/親しみ)が機能しているか

### 基準3: 参考サイトの咀嚼度(10点)
- 5つの参考サイトの「いいとこ取り」になっていないか
- 各サイトから取り入れた要素がALPS LABの世界観に統合されているか

### 基準4: 実装可能性(10点)
- HTML/CSS/JS+GSAPで実装可能なデザインか
- Coderが追加質問なしで実装着手できる粒度のワイヤーフレームか

### 基準5: 動きの設計の具体性(10点)
- 「動きを重視」という要件に対して、具体的にどこに何の動きを入れるかが明確か
- パフォーマンスを犠牲にしすぎていないか(モバイル対応含む)

## Coder Agent 用評価基準(50点満点)

### 基準1: デザイン一貫性(10点)
- Designerの意図通りに実装されているか
- トンマナ(ダーク・ストイック+セクションごとの親しみ表現)が守られているか

### 基準2: コード品質(10点)
- セマンティックHTML(`<header>`, `<nav>`, `<main>`等の適切使用)
- CSSの整理(BEM命名 or CSS変数の活用)
- JSの可読性(コメント・関数分割)

### 基準3: パフォーマンス(10点)
- 画像の最適化(WebP・適切なサイズ・lazy load)
- 不要なライブラリの読み込みなし
- LCP 2.5秒以内が見込めるか

### 基準4: アクセシビリティ(10点)
- 全画像にalt属性
- キーボード操作可能(Tabフォーカス順序適切)
- コントラスト比 WCAG AA以上
- フォームのlabel紐付け

### 基準5: レスポンシブ対応(10点)
- 1280 / 1024 / 768 / 480 全てで崩れなし
- モバイル時のメニュー動作
- 動画→静止画切替などの最適化

## 合格基準の採点後のアクション

| 合計点 | アクション |
|---|---|
| 45~50点 | 即合格、次工程(Critic Agent)へ |
| 40~44点 | 合格(任意改善点を記録)、Critic へ |
| 35~39点 | 必須改善点に対応してから再採点 |
| ~34点 | 大幅見直しが必要、オーケストレーターに相談 |

# 🟡 Phase 2: 卓越基準(50点を目指す品質追求)

> **Critic Agent の責務**。合格基準クリア後に、業界水準・初見ユーザー視点で再評価。
> 100点満点中 80点以上が「商業リリース可能」、90点以上が「業界トップレベル」。

## Web デザイン視点(10軸×10点 = 100点満点)

### W1: コンセプト・ブランド表現(10点)★★★
- ブランドの世界観・思想が視覚から伝わるか
- 抽象的な比喩だけでなく、具体的なビジュアル(データ・図版・実体写真)で語れているか

### W2: 情報設計・サイトマップ(10点)★★★
- ページ間の関係性・サイト構造の論理性
- ページ過多になっていないか、内容重複がないか

### W3: ナビゲーション設計(10点)★★★
- 訪問者が迷わず目的のページに辿り着けるか
- メガメニュー・パンくずリスト・セカンダリナビの有無

### W4: ファーストビューの完成度(10点)★★★
- 最初の3秒で「何のサイトか」が伝わるか
- 業界知識ゼロの人が混乱しないか
- セカンダリ CTA の有無

### W5: コンバージョン誘導設計(10点)★★★
- 体験予約・お問い合わせまでの導線設計
- 専用フォーム vs 汎用 CONTACT の使い分け
- 限定性・希少性の演出

### W6: ビジュアル階層・タイポグラフィ(10点)★★
- 文字サイズ・余白・色の使い分けが意図的か
- 行間(line-height)、tabular-nums など細部の整い

### W7: トラスト要素(信頼設計)(10点)★★
- 第三者評価・実績・透明性の表現
- 顧問医師・栄養士の実名+顔+経歴
- メディア掲載ロゴ・受賞歴
- 累計実績の数字
- 認証マーク

### W8: アクセシビリティ(10点)★★
- 誰でも使えるか
- フォーカス可視化のブランド対応
- スクリーンリーダー対応

### W9: レスポンシブ・デバイス対応(10点)★
- モバイル・タブレットでの体験品質
- タッチターゲット 44px 以上
- iOS Safari の 100vh 問題対応

### W10: コンテンツの質・量バランス(10点)★
- 必要な情報が必要な量だけあるか
- FAQ 20件以上、STORIES 15件以上が目安

## 卓越基準の採点後のアクション

| 合計点(100点) | 判定 | アクション |
|---|---|---|
| 90〜100 | ⭐ 業界トップレベル | リリース準備完了 |
| 80〜89 | ⭕ 商業リリース可能 | 任意の磨き込み(必須ではない) |
| 70〜79 | △ 改善必要 | 🔴最優先項目に対応 |
| 60〜69 | ⚠ 大幅改修 | 🔴+🟡項目に対応してから再評価 |
| ~59 | ✕ 設計から見直し | オーケストレーターに相談、必要なら Designer へ差し戻し |

# セルフリファインの実装方法(プロンプトテンプレート)

## 合格基準のセルフチェック(Reviewer / Designer / Coder 用)

```
## セルフチェック(合格基準)

私は本タスクの成果物に対して、以下5項目を採点します(各10点)。

### 基準1: {基準名}
- 採点: X/10
- 良い点: ...
- 改善点: ...

### 基準2〜5(同上)

### 合計: X/50

### 判定
- [ ] 合格(40点以上)→ Critic Agent へ
- [ ] 改訂が必要(40点未満)→ 必須改善点を反映して v2.0 を作成
```

## 卓越基準のクリティーク(Critic 用)

```
## クリティーク(卓越基準)

業界ベンチマークと比較して、以下10軸で採点します(各10点)。

### W1〜W10(同上)
- 採点: X/10
- 業界水準との比較: {具体的なサイト名と差分}
- 改善案: {具体的・実装可能な提案}

### 合計: X/100

### 改善優先度
🔴 最優先(必須改善):
🟡 効果大(推奨):
🟢 余力(任意):
```

## なぜ2層構造なのか

`09_meta/final_review.md` 第五部で詳述している通り、**従来の単一基準は「身内採点」になりやすい**。

- Reviewer:**コードの正しさを担保**(Phase 1)
- Critic:**業界水準・ユーザー視点で品質追求**(Phase 2)

両方をクリアして初めて、**自己採点の構造的限界を超える**ことができる。
